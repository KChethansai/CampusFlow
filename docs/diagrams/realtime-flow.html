CampusFlow — Realtime Flow (Socket.IO)

Sources: config/socket.js, services/notification.service.js, services/digest.service.js, server.js, src/store/useSocket.

1. Handshake (WSS)

Client connects with socket.handshake.auth.token = current 15m access token. authenticateSocket runs jwt.verify(token, env.secretKey), then re-checks DB like verifyToken: user exists, isActive, and !changedPasswordAfter(decoded.iat). Failure → next(new Error('Not authorized…')), connection refused. No token storage on the socket beyond socket.data.user {id, institution, role}.

↓

2. Tenant / room scoping

  • Singleton initSocket(httpServer) (one instance per process, hot-reload safe).
  • On connect: socket.join(`user:${id}`) + socket.join(`institution:${institution}`) — every event is tenant-scoped by construction.
  • CORS mirrors HTTP: origin: env.clientUrls, credentials: true.
↓

3. Fan-out (fire-and-forget)

  • emitToUser(userId, event, payload) → room user:{id} (request updates, grades, personal notifications).
  • emitToInstitution(institutionId, event, payload) → room institution:{id} (announcements, attendance sessions, events).
  • Published via services/notification.service.js (publishRealtimeToUser/Institution). Emits are wrapped in try/catch — they never throw into the DB write path.
↓

4. Notification prefs + weekly digest

Per-user preferences at GET/PATCH /notifications/preferences; read-state via PATCH /notifications/:id/read. digest.service.js runs cron.schedule('0 6 * * 0') (started in server.js via startDigestJob()): unread count + due-soon assignments per role → email via Nodemailer, no-op without SMTP.

Covered by the socket test suite (handshake + room scoping) in backend/tests/.
