CampusFlow — Authorization & Tenant Model

Sources: models/UserModel.js (role enum), middlewares/verifyToken.js, utils/scope.js, utils/sanitize.js, APIs/*.js, APIs/institutionAPI.js.

6 roles (UserModel.role enum): super_admin · college_admin · hod · faculty · student · placement_officer. Every user belongs to one institution (tenant root); hod/faculty may carry a department. JWT role claims are never trusted — verifyToken reloads role, isActive, passwordChangedAt from DB per request.
Mechanism: list queries add tenantFilter(req) = {institution: req.user.institution}; single-object reads/mutations go through scopedOne(model, req, id) = findOne({_id, institution}) (cross-tenant id → 404, IDOR/BOLA guard). Writes are allowlisted via pick() / sanitize.js (+ academicScope.js); hod writes additionally constrained to own department via requireDepartment(req) (fail-closed 403). Pagination capped (pageParams, max 200).

Super-admin-only surfaces: tenant lifecycle (institutionAPI.js writes) and anything crossing institutions. There is no cross-tenant read path: institution scoping is applied in the controller/service layer on every object route, with server-enforced workflow transitions (requests, drives, assignment status) and auditLog on writes.
Regression cover: security suite (RBAC/tenant isolation) + integrity suite in backend/tests/.
