CampusFlow — Authentication Sequence (15m access + 7d rotating refresh)

Sources: controllers/authcontroller.js, utils/token.js, models/RefreshTokenModel.js, models/UserModel.js, config/env.js.

Not a 1-day JWT flow. Access tokens live 15m (ACCESS_TOKEN_EXPIRES); refresh tokens live 7d (REFRESH_TOKEN_EXPIRES_DAYS), are DB-backed, single-use, and rotate on every refresh.
  1. Login — POST /api/v1/auth/login {email, password} (rate-limited 10/15 min). Server finds user, checks isActive, compares with bcryptjs.compare(). On success: signAccessToken() (claims sub/role/institution/department, 15m) + signRefreshToken() (sub/type:jti, 7d). Refresh stored as sha256 hash in RefreshTokenModel with expiresAt; also set as httpOnly cookie (getCookieOptions()). Client persists {user, accessToken, refreshToken} to localStorage cf_auth.
  2. API calls — Authorization: Bearer <access> → verifyToken re-loads role/isActive/passwordChangedAt from DB per request; rejects post-password-change sessions (changedPasswordAfter(iat) → 401).
  3. Refresh (rotation) — POST /api/v1/auth/refresh with body or cookie token. Server verifies signature, loads stored hash with revokedAt: {$exists:false}, marks it revoked, issues a brand-new pair. A 15s grace window absorbs double-submit retries.
  4. Reuse detection → revoke-all — presenting an already-rotated (or unknown) refresh token means theft: server runs RefreshToken.updateMany({user}, {revokedAt: now}), revoking the whole family; client must re-login.
  5. Password-change invalidation — change-password / reset-password bump passwordChangedAt; any access token with iat before it is rejected, and refresh rotation against a pre-change token revokes the family instead of rotating.
  6. Logout (refresh-tolerant) — POST /api/v1/auth/logout revokes the presented refresh session even with an expired access token, clears the cookie; client clears cf_auth. Password-reset uses emailed token falling back to in-app notification without SMTP.
  7. Registration is privileged — POST /auth/register requires verifyToken('super_admin','college_admin'); there is no public self-signup.
Lifetimes configurable via ACCESS_TOKEN_EXPIRES / REFRESH_TOKEN_EXPIRES_DAYS (legacy aliases JWT_ACCESS_EXPIRES / JWT_REFRESH_EXPIRES_DAYS).
